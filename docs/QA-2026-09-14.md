Method. Installed build through `./install-runtime.sh update-background` (rollback snapshots in `~/Library/Application Support/Language Relay/Rollback/`); the panel opened by a synthetic click on the status item (position from the AX tree), screenshots by `screencapture -l <windowID>`, keys and clicks by CGEvent; offscreen layouts by `--render-ui out.png [--expanded] [--health ready|denied|unavailable]`; Tab order by `--key-loop`; `make test` (`--self-test` + `--ui-self-test`) and `make design-check`. Screenshots: `/tmp/codex-screenshots/apps-wave4/relay-*.png`. Environment note: the machine was in use during the run, so the transient popover closed on every foreign app activation (`_NSPopoverProcessResignKey` in the trace); rows marked `live` were repeated until a clean run was captured, rows marked `offscreen` or `self-test` rest on the headless checks.

Observations, not fixed: the collapsed panel keeps about 40 pt of air between `setup` and the footer (the disclosure host is 64 pt for both states, so the layout does not jump); the setup card shows the bridge's raw last status (`success-events-verified`, `task-exit-3`) which reads as noise to a person; the `hs` CLI blocked twice during the run (Hammerspoon IPC busy), the app's bounded 0.35 s calls degrade to the last known state as designed.

Fixes in 2.3.8: `LayoutPilotRootView.performKeyEquivalent` (Command-W), `RelayButton.canBecomeKeyView` + explicit key view loop on the popover window (`installKeyLoop`) and Tab handled inside `RelayButton.keyDown`, `PanelHealth.keys` for the footer, `--render-ui --health` and `--key-loop` for QA, page CSS (`.hero-proof .suite-caption` wraps, `.download-meta code` breaks).
