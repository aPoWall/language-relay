## The watchdog, check by check (`tests/bridge-watchdog.lua`)

The bridge is loaded into a stub Hammerspoon, so no event tap is created, no accessibility tree is read and no
configuration is touched. The clock is a stub too, so the five seconds cost no wall time.

| check | expectation | result |
|-------|-------------|--------|
| the reading | tap, busy, secureInput, lastStatus, settings, five second lifetime | pass |
| fresh flag | a flag two seconds old holds the gesture and survives it | pass |
| stale flag | a flag nine seconds old is seen as stale, the next gesture releases it and runs | pass |
| status is read only | `layoutPilotStatus()` reports `busyStale` without repairing it | pass |
| the path without a reset | an accessibility read that raises inside the repair ends `fix-error` with the flag down | pass |
| the release is written down | a release with nothing after it leaves `busy-timeout`, a second release finds nothing | pass |
| restart | `layoutPilotRestart()` drops the flag and brings the tap back | pass |
| the status line | seven fields in a fixed order, version first | pass |
| one writer | the flag is assigned only in its declaration and in `layoutPilotSetBusy` | pass |

The fifth row is the one the sprint asked for: before this wave the repair raised the flag and then read the
accessibility tree unprotected, so an error there left `layoutPilotBusy = true` for the life of the
configuration and every gesture after it returned false without a word.

## Control walk (rules 38, 41) · the controls this wave added

| control | press | what changed |
|---------|-------|--------------|
| `bridge-status` | none, it is a reading | prints `bridge · <line>`; five readings, five texts: `ready`, `tap off`, `no answer`, `busy 9s · stuck`, `2.3.3 · reload for 2.4.0`, asserted in `--ui-self-test` |
| `bridge-restart` | one press | runs `layoutPilotRestart()` on the bridge: the run token moves, the busy flag drops, the gesture tap comes back; the row then reads `restarted by hand` or `restart refused`, and the panel is rebuilt |
| launch read | no press, one read | a healthy bridge is only asked to re-read its settings; a tap that is off or a stuck flag gets one restart and the row says `restarted at launch, <reason>` |

The press on `bridge-restart` is verified at the bridge level by the lua test (the flag drops, the tap returns)
and at the surface level by the self-test (the control exists, keeps its 36 pt, carries its identifier and its
accessibility help). The press itself was not fired on the owner's machine: firing it restarts the gesture tap
of the running bridge, which is a live change to the machine the owner is typing on. It belongs to the VM stand
of rule 50 or to the owner's own hand.
